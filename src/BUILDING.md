# Сборка резюме

Этот файл содержит всё необходимое, чтобы собрать обе версии резюме на новом
устройстве. Для сборки нужен только Typst CLI. Сторонние Typst-пакеты проект не
использует.

## Результат сборки

Из двух входных файлов создаются два PDF в корне репозитория:

| Исходный файл | Результат |
| --- | --- |
| `src/resume-viacheslav-shalygin-ru.typ` | `resume-viacheslav-shalygin-ru.pdf` |
| `src/resume-viacheslav-shalygin-en.typ` | `resume-viacheslav-shalygin-en.pdf` |

`src/template.typ` содержит общий шаблон и самостоятельно собираться не должен.
Русская версия использует фотографию `src/assets/photo.png`; в английской версии
фотография отключена.

## 1. Получение репозитория

```shell
git clone https://github.com/vshalygin/resume.git
cd resume
```

Все приведённые ниже команды необходимо выполнять из корня репозитория, где
находятся `README.md`, каталог `src` и каталог `.vscode`.

## 2. Установка Typst

Известная рабочая версия компилятора для этого проекта: **Typst 0.15.1**.

Сначала можно установить актуальную версию Typst. Если в будущем она окажется
несовместима с исходниками или изменит переносы строк, следует установить
Typst 0.15.1 со страницы релизов:

<https://github.com/typst/typst/releases>

### Windows

```shell
winget install --id Typst.Typst
```

После установки нужно закрыть и заново открыть терминал или VS Code, чтобы
обновился `PATH`.

### macOS

```shell
brew install typst
```

### Linux

Нужно скачать архив для своей архитектуры со страницы релизов Typst, распаковать
исполняемый файл `typst` и поместить его в каталог, входящий в `PATH`.

Если установлен Rust, Typst также можно установить через Cargo:

```shell
cargo install --locked typst-cli
```

### Проверка установки

```shell
typst --version
```

Команда должна вывести версию компилятора и завершиться без ошибки.

## 3. Проверка шрифта

Шаблон использует шрифт Arial. Он обычно уже установлен в Windows, но может
отсутствовать в Linux или macOS.

Windows:

```shell
typst fonts | findstr /I Arial
```

Linux и macOS:

```shell
typst fonts | grep -i Arial
```

Если Arial отсутствует, его необходимо установить разрешённым для операционной
системы способом. Замена Arial другим шрифтом в `src/template.typ` может изменить
переносы строк и количество страниц.

Для максимально близкого воспроизведения существующих PDF следует использовать
Typst 0.15.1 и Arial.

## 4. Сборка из командной строки

Русская версия:

```shell
typst compile src/resume-viacheslav-shalygin-ru.typ resume-viacheslav-shalygin-ru.pdf
```

Английская версия:

```shell
typst compile src/resume-viacheslav-shalygin-en.typ resume-viacheslav-shalygin-en.pdf
```

После успешной сборки оба PDF находятся в корне репозитория. Повторная сборка
перезаписывает соответствующий PDF.

Для автоматической пересборки одного документа во время редактирования можно
временно использовать:

```shell
typst watch src/resume-viacheslav-shalygin-ru.typ resume-viacheslav-shalygin-ru.pdf
```

или:

```shell
typst watch src/resume-viacheslav-shalygin-en.typ resume-viacheslav-shalygin-en.pdf
```

Остановить режим наблюдения можно сочетанием `Ctrl+C`.

## 5. Сборка в VS Code

VS Code не обязателен, но в репозитории уже находятся готовые задачи из
`.vscode/tasks.json`.

1. Установить VS Code.
2. При необходимости установить расширение **Tinymist Typst**.
3. Убедиться, что команда `typst --version` работает во встроенном терминале
   VS Code.
4. Открыть именно корень репозитория через `File -> Open Folder`.

Доступные задачи:

- `Resume: Build Russian PDF`;
- `Resume: Build English PDF`;
- `Resume: Build all PDFs`.

`Ctrl+Shift+B` запускает задачу `Resume: Build all PDFs`. Для сборки одной версии
нужно открыть `Terminal -> Run Task` и выбрать соответствующую задачу.

Задачи запускают Typst CLI из `PATH`. Наличие расширения Tinymist само по себе не
гарантирует, что команда `typst` доступна системе.

Автоматический экспорт Tinymist отключён в `.vscode/settings.json`. Это сделано,
чтобы редактор не создавал PDF для `src/template.typ` и не собирал произвольный
открытый файл. Для обычной сборки следует использовать задачи VS Code или команды
из предыдущего раздела.

## 6. Что проверять перед публикацией

После изменения исходников нужно:

1. Собрать обе версии.
2. Открыть оба PDF и проверить все страницы визуально.
3. Убедиться, что каждый документ занимает не более двух страниц A4.
4. Проверить переносы строк, отступы, фотографию и кликабельность ссылок.
5. Убедиться, что русская и английская версии содержат согласованные факты,
   должности и даты.
6. Добавить обновлённые `.typ`, оба PDF и необходимые ресурсы в один коммит.

В этом репозитории нет CI: готовые PDF собираются локально и хранятся в Git вместе
с исходниками.

## 7. Основные файлы

- `src/resume-viacheslav-shalygin-ru.typ` — содержание русского резюме;
- `src/resume-viacheslav-shalygin-en.typ` — содержание английского резюме;
- `src/template.typ` — общая вёрстка, размеры и типографика;
- `src/assets/photo.png` — фотография для русской версии;
- `.vscode/tasks.json` — команды локальной сборки;
- `.vscode/settings.json` — настройки Typst/Tinymist для проекта.
